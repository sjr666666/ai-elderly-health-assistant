## 1. 设计概述

### 1.1 设计理念

AI药管家系统第一阶段聚焦**老人端**的完整体验设计，以"易读、易点、易听"为核心理念：

- **易读**：18px 基准大字号、line-height 1.8、高对比度配色（主色 #4A90E2 蓝、文字 #3D3D3D），降低老年人视觉负担
- **易点**：大圆角（36px）、大按钮（≥48px 高）、大间距（容器 padding 40-60px），方便老年人精准点击
- **易听**：百度 TTS 语音播报用药指导与提醒内容，支持语速调节，照顾视力衰退用户
- **强反馈**：颜色递进（蓝→橙→红→深红）、粒子庆祝动画、Toast 提示、加载动画，提供充分视觉反馈
- **可降级**：用药计划本地缓存、紧急助手本地急救指南、药品搜索本地建议库，断网仍可用

家属端为第二阶段规划内容，将采用独立的"轻量、即时、便携"设计语言（蓝色冷色调 + 14px 字号 + 移动端 480px），第一阶段仅在附录中预告设计思路。

### 1.2 设计目标（第一阶段）

| 目标 | 老人端 |
| --- | --- |
| 易用性 | 70 岁以上老人独立可用，核心任务 3 步内完成 |
| 可读性 | 18px 基准字号、line-height 1.8 |
| 视觉反馈 | 颜色递进 + 粒子动画 + TTS 播报 |
| 情感化 | 暖色调（杏+薄荷绿+科技蓝）+ 大圆角 + 庆祝动画 |
| 适配场景 | 桌面/平板/手机三端响应 |
| 健壮性 | AI 服务降级 + 离线缓存 + 双保险漏服监控 |

## 2. 设计规范

### 2.1 色彩方案

| 类别 | 色值 | 用途 |

| 主色浅 | `#7FB3F5` | 悬浮态、辅助元素 |

| 暖色（杏色） | `#F5C6A5` | 主题渐变起点 |

| 奶油白 | `#FAF7F2` | 页面背景主色 |
| 奶油深 | `#F0EBE3` | 边框、分割线 |
| 文字主色 | `#3D3D3D` | 正文文字 |
| 文字次色 | `#6B6B6B` | 辅助文字 |
| 文字弱色 | `#9B9B9B` | 占位符、提示 |
| 成功 | `#5CB85C` | 成功状态 |
| 警告 | `#F5A623` | 警告状态 |
| 危险 | `#E74C3C` | 错误、删除、过期 |
| 紧急 | `#6B5B95` | 紧急模式 |

> 家属端色彩方案（蓝色冷色调）将在第二阶段文档中展开。

### 2.2 字体规范

#### 2.2.1 字族定义

```css
font-family: -apple-system, BlinkMacSystemFont, 'PingFang SC',
  'Hiragino Sans GB', 'Microsoft YaHei', 'Helvetica Neue', Helvetica, Arial, sans-serif;
```

优先使用系统原生字体（苹方/微软雅黑），保证渲染性能与原生体验。

#### 2.2.2 字号层级（老人端，基准 18px，line-height 1.8）

| 层级 | 字号 | 用途 |
| --- | --- | --- |
| H1 主标题 | 32-36px | 页面主标题（如登录页"AI 药管家"） |
| H2 标题 | 24-28px | 卡片标题、模态框标题 |
| H3 副标题 | 20-22px | 区块小标题 |
| 正文 | 18px | 主要文字内容 |
| 辅助 | 16px | 次要文字、标签 |
| 小字 | 14px | 时间戳、备注 |

### 2.3 圆角规范

| 类别 | 圆角 | 用途 |
| --- | --- | --- |
| radius-small | 12px | 小按钮、标签 |
| radius-medium | 20px | 输入框、中按钮 |
| radius-large | 28px | 卡片 |
| radius-xl | 36px | 模态框、顶栏 |
| 按钮 | 16-20px | 各类按钮 |
| 输入框 | 16-20px | 表单输入 |
| 卡片 | 28-36px | 主要卡片 |
| 模态框 | 24-36px | 弹窗 |

### 2.4 间距规范

| 类别 | 数值 | 用途 |
| --- | --- | --- |
| 容器内边距 | 40-60px | app-container padding |
| 卡片内边距 | 24-48px | 主要卡片 padding |
| 元素 gap | 8/12/16/24px | flex/grid gap |
| 模态框 padding | 40-50px | 弹窗内边距 |
| 响应式收缩 | 30/40px（1200px）、20/24px（768px） | 中小屏适配 |

### 2.5 阴影规范

```css
--shadow-soft: 0 8px 32px rgba(0, 0, 0, 0.08);     /* 默认卡片 */
--shadow-medium: 0 12px 48px rgba(0, 0, 0, 0.12);   /* 悬浮卡片 */
--shadow-strong: 0 16px 64px rgba(0, 0, 0, 0.16);   /* 模态框 */
--shadow-glow-blue: 0 0 40px rgba(74, 144, 226, 0.3);   /* 蓝色发光 */
--shadow-glow-mint: 0 0 40px rgba(152, 212, 187, 0.3);  /* 薄荷发光 */
```

老人端阴影较重，强化层次感与悬浮感，方便老人识别可点击元素。

### 2.6 动效规范

```css
--transition-fast: 0.2s cubic-bezier(0.4, 0, 0.2, 1);
--transition-medium: 0.3s cubic-bezier(0.4, 0, 0.2, 1);
--transition-slow: 0.5s cubic-bezier(0.4, 0, 0.2, 1);
```

特殊动效：
- **header shimmer**：顶栏渐变流光动画
- **loading spinner**：旋转加载动画
- **toast-enter/exit**：Toast 进入退出动画
- **fadeInUp**：模态框淡入上滑
- **pulse**：脉冲动画（紧急按钮）
- **粒子庆祝**：服药确认后触发粒子飞散动画

### 2.7 图标规范

- **统一使用 SVG 图标**，不使用 emoji（用户偏好）
- 老人端图标较大（24-32px）
- 家属端 SVG 图标主色为 `#3A7BC8`（蓝色）
- 老人端 SVG 图标支持多彩（蓝/绿/橙/红）
- 性别头像：男 `#5B9BD5`、女 `#E88BA8`

### 3.2 紧急事件与漏服处理流程（第一阶段）

```
老人触发紧急模式 / 漏服超时 10 分钟
    ↓
后端创建 emergency_event / 标记 plan 为 missed
    ↓
查询老人所有 active 监护人
    ↓
逐个写入短信通知日志（sms_notification_log，模拟发送）
    ↓
老人端 WebSocket 推送 notify_family 阶段提醒
    ↓
数据已完整留痕，第二阶段接入真实短信网关 + 家属端 UI 即可形成完整闭环
```

### 7.3 视觉设计原则

1. **老人端"暖 + 大 + 厚"**：
   - 暖色渐变背景（杏色 + 薄荷绿）
   - 18px 大字号、line-height 1.8
   - 36px 大圆角、重阴影
   - 蓝色发光效果突出可点击元素

2. **状态色统一**：
   - 红 = 危险/紧急/漏服/过期
   - 橙 = 警告/临期/待处理
   - 绿 = 成功/已服/已处理
   - 蓝 = 主色/待服/链接

3. **渐进式提醒视觉差异**：
   - 蓝 → 橙 → 红 → 深红 颜色递进
   - 🔔 → ⏰ → ⚠️ → 🚨 图标语义递进
   - 紧迫感逐级递增，引导老人及时服药

> 家属端视觉设计原则（"冷 + 小 + 轻"）将在第二阶段文档中展开。

## 附录：第二阶段预告（家属端规划）

> 本附录仅作设计思路预告，最终设计可能在第二阶段实施时调整。家属端目前为雏形，许多想法尚未实现。

### A.1 设计目标

家属端定位为"轻量、即时、便携"的移动端监护应用，与老人端形成"老人主动管理 + 家属被动监护"的双端闭环：

- **轻量**：移动端 max-width 480px，单手操作友好
- **即时**：3 秒轮询未读通知，紧急事件秒级触达
- **便携**：iPhone 刘海屏 + Android 大屏全适配，随时随地查看老人状态

### A.2 设计语言（预告）

| 维度 | 老人端（第一阶段） | 家属端（第二阶段预告） |
| --- | --- | --- |
| 色调 | 暖色（杏色 + 薄荷绿 + 科技蓝） | 冷色（蓝色 #3A7BC8 + 灰白 #F4F6F9） |
| 字号 | 18px 基准，line-height 1.8 | 14px 基准，line-height 1.5 |
| 圆角 | 36px 大圆角 | 12px 中等圆角 |
| 阴影 | 重阴影 + 发光 | 轻阴影/边框 |
| 设备 | 桌面优先 + 响应式 | 移动端优先 |
| 情感 | 温暖、关怀、鼓励 | 专业、清晰、即时 |

### A.3 功能模块（预告）

| 模块 | 关键能力 | 设计思路 |
| --- | --- | --- |
| 仪表盘 | 关联老人/事件/通知统计 + 老人列表 | 3 列统计卡 + 折叠绑定表单 + 老人卡片列表 |
| 老人详情 | 今日用药 + 紧急事件 + 临期药品 | 并发加载 4 接口，状态色统一 |
| 通知记录 | 漏服/紧急/临期通知 + 未读统计 | 左侧蓝色边线 + 类型标签 + 状态 badge |
| 个人中心 | 资料编辑 + 密码修改 + 退出 | 折叠式编辑表单 |

### A.4 与第一阶段的衔接

第一阶段已在后端完整预留家属端所需的全部数据能力：

- `guardian_elder_relation` 表：家属-老人绑定关系（含解绑/恢复逻辑）
- `sms_notification_log` 表：短信通知日志（模拟发送，第二阶段接入真实网关）
- `emergency_event` 表：紧急事件留痕
- `elder_notification` 表：老人端通知（含绑定通知推送）
- `hasPermission(guardianId, elderId)` 权限校验：家属访问老人数据前的强制校验
- 渐进式提醒 `notify_family` 阶段：超时 10 分钟自动写入短信通知日志

第二阶段只需在前端实现家属端 UI 并接入真实短信网关，即可形成"老人触发 → 数据留痕 → 家属接收"的完整监护闭环，无需改动后端核心逻辑。
